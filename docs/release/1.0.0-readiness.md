# Tiber 1.0.0 release readiness

Status: candidate preparation complete; human release merge and marketplace
submission remain intentionally pending.

## Candidate contract

The release candidate is the exact tree produced by the Slice 22 ordinary pull
request. Its required GitHub gates are quality, acceptance/package, full core
mutation at 100%, and the aggregate CI gate. The package gate creates the npm
tarball, installs that tarball into a clean stock-Pi agent directory outside the
repository, exercises Tiber through Pi RPC, and verifies package contents.
Publication is never performed by a pull-request workflow.

Supported runtime:

- Node.js `>=22.23.1 <23`
- stock `@earendil-works/pi-coding-agent`, `pi-ai`, and `pi-tui`
  `>=0.84.2 <1`
- `typebox >=1.3.7 <2`
- npm 10.9.8 is the contributor/CI lock; publication uses the separately pinned
  OIDC-capable npm 11.5.1 CLI

The tarball contains compiled JavaScript, user documentation, licenses, the Pi
extension manifest, prompts, skills, and the default workflow. It excludes
TypeScript source, tests, repository automation, Rust/native artifacts,
declaration files, and source maps. Runtime installation has no native or
install-time build dependency.

## Human-gated release boundary

Release PR #9 is generated by release-please and must remain open until an
explicit human reviews and merges it. The Slice 22 delivery commit carries
`Release-As: 1.0.0`, causing release-please to prepare the stable version without
allowing Tiber or ordinary auto-merge to merge the release PR. After that human
merge, the protected release workflow creates the tag and GitHub Release and
publishes `@jwilger/tiber@1.0.0` through npm OIDC with provenance.

Before human merge, confirm the release PR names `1.0.0`, targets the exact
Slice 22 mainline revision, has every required check green, and retains the
release-PR auto-merge prohibition. After publication, install the immutable
version in a fresh directory with:

```shell
pi install npm:@jwilger/tiber@1.0.0
```

Run `/tiber:doctor`, inspect `/tiber:tasks`, and complete the representative
signed-task smoke workflow documented by package acceptance. Record the npm
integrity/provenance and GitHub Release URL.

## Marketplace boundary

Marketplace submission is downstream of the stable npm publication and must
not claim an unpublished package. Once `npm:@jwilger/tiber@1.0.0` resolves and
the clean install succeeds, submit that exact immutable package identity to the
Pi package marketplace with the repository, npm, release, license, supported
Pi/Node range, install command, and security-policy links. Record the resulting
listing or submission URL. If no separate marketplace intake exists, record the
maintainer-confirmed discovery mechanism rather than inventing a receipt.
